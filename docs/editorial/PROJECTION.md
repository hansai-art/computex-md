# PROJECTION — 投影方法論

> 研究報告是一堆材料。文章是這堆材料在「一條敘事線」上的投影。
> 這份檔案是那個投影怎麼做的方法論——研究 → **投影邏輯** → 文章 的中間層。
>
> 走 [REWRITE-PIPELINE](../pipelines/REWRITE-PIPELINE.md) 的 **Step 2.0 投影藍圖** 時讀本檔。產物是一份 `reports/article-projection/{slug}.md`，寫手照它把研究報告投影成文章本體。

---

## 一、為什麼需要投影這一層

### 病：每個 section 單獨看都完整，接起來卻沒有一個更大的東西

一篇文章可以每一段都寫得乾淨、每個小標題底下都是一則完整的介紹，然後整篇讀完是空的。原因是：**這些 section 是按「面向」排列的，不是按「論點的推進」排列的。**

寫黃威融、寫李惠貞、寫紙本、寫 BEST100、寫 DesignBIZ——每一塊都是一則關於那個面向的迷你介紹。把它們接起來，你得到一份導覽，不是一個論證。你幾乎可以把中間幾個 section 的順序打亂，文章讀起來差不多。這就是問題：**section 之間是加法（一個面向加一個面向），不是乘法（一步推進下一步）。**

主軸句在開頭和結尾各講一次，但中間沒有人在推進它。讀者拿到一堆整理好的知識，卻拿不到一個「所以呢」。文章因此變得很空泛，很可惜。

（誕生：2026-07-13 哲宇跟朋友陳睨聊天後發現，Taiwan.md 的文章反覆踩這個。研究做得越足、面向越多，這個病越明顯——因為材料多，寫手更傾向「把面向鋪滿」而不是「挑材料建論證」。）

### 這一層跟 Stage 0 觀點、Stage 2 寫，差在哪

三件事，三個階段，不要混在一起：

| 階段             | 時機                     | 做什麼                                                                                            | 產物                         |
| ---------------- | ------------------------ | ------------------------------------------------------------------------------------------------- | ---------------------------- |
| **Stage 0 觀點** | 研究**之前**             | 決定角度：spine 類型、六核心問題、要在意的畫布                                                    | 一句主軸錨 + 一張面向畫布    |
| **Stage 1 取材** | 研究                     | 把材料撈回來                                                                                      | 研究報告（一堆材料）         |
| **投影 (本檔)**  | 研究**之後**、寫**之前** | 桌上有整堆材料了，設計論點與骨架：哪一個論點、哪個順序建它、每個 section 做什麼全局功能、砍掉什麼 | 投影藍圖（一份可執行的結構） |
| **Stage 2 寫**   | 投影之後                 | 照藍圖把材料投影成句子                                                                            | 文章                         |

Stage 0 給你**角度**，投影給你**建築**，Stage 2 給你**句子**。以前 pipeline 從角度直接跳到句子，中間那個「總編輯看完整堆材料、想清楚這篇到底要怎麼長」的動作沒有人做，於是寫手拿著面向清單，一個面向寫一段。**投影就是把那個總編輯的動作，變成一個明確的、必經的、有產物的階段。**

## 二、投影是一個選擇 + 連結的動作，不是一個鋪滿的動作

投影的本質是**減維**。研究報告是高維的（每個面向都是一個維度），文章是一維的（讀者從第一個字讀到最後一個字，一條線）。把高維壓成一維，你**必然要丟掉東西**，而且**必然要決定順序**。這兩件事——丟什麼、怎麼排——就是投影邏輯的全部。

所以投影的第一性原理是：

- **它是減法。** 好的投影丟掉大量研究材料。丟不下手 = 還沒找到論點。
- **它是選擇。** 判準在「這個材料**服不服務這一次的論點**」，不在材料本身重不重要。同一堆材料，換一個論點，該留的該丟的完全不同。
- **它是連結。** section 之間要能說出「上一步推到這裡，所以下一步必須是……」這種推進關係，而非平放成「還有一個面向是……」的並列。
- **順序是內容的一部分。** 把 section 順序打亂還能讀 = 你排的是目錄不是論證。

## 三、投影方法論——六個動作

拿到一份過了 `research-report-health` 的研究報告，做這六件事，產出投影藍圖。

### 動作 1：找論點（一句有張力、要被賺到的主張——比主題、比主軸摘要都更尖）

Stage 0 的主軸句（「Shopping Design 花二十年把設計變成動詞」）是一句**摘要 / 錨點**。論點比它更尖：它是一個**主張**，有邊、會被賺到、整篇文章都在替它出力。

**判準一句話：一個聰明的讀者能不能不同意它，或者這篇文章得不得證明它？**

- ❌「Shopping Design 是一本重要的台灣設計雜誌」——沒有人會不同意，這是主題不是論點。
- ✅「Shopping Design 真正教會台灣的，不是品味，是『分辨』這件事可以被練——而同一個動作，最後把讀者最該分辨的對象，變成了 Shopping Design 自己。」——有張力、會被賺到、需要整篇證明。

論點是**一句話**。它裝著文章的意圖。之後每個 section 都替它出力，替不了力的 section 就是該砍的。

**論點類型跟 spine 類型綁定**（per [REWRITE-PIPELINE Step 0.1.5](../pipelines/REWRITE-PIPELINE.md) + [REFLEXES #77](../semiont/REFLEXES.md) + [MANIFESTO §13 立體地愛](../semiont/MANIFESTO.md)）：

- **矛盾驅動題**（爭議 / 政策辯論 / 內在張力人物）→ 論點可以是**辯論式的主張**（一個可被反駁的 claim，文章替它辯護）。
- **多觀點立場議題題**（進行中的公共議題，多方都有正當立場；[Step 0.1.5](../pipelines/REWRITE-STAGE-0-VIEWPOINT.md) 第三型）→ 論點是**「這場爭論的形狀是什麼」＋「誰的帳沒被算」**：矛盾當脊椎，但**不收束成一方勝出**；文章的工作是讓分歧的形狀變得可讀，並指出爭論的重心被放錯在哪。讀者離場時該知道自己還缺哪一塊判斷依據，而不是被推向一個結論。
- **立體群像題**（受愛戴的機構 / 傳統 / 集體記憶 / 多數人物）→ 論點是**綜合式 / 統合式的洞見**：不對立、不找碴，但**仍然是一個有推進的具體主張**，不是一句慶祝的摘要。立體 ≠ 沒有論點；立體的論點是「這一整群面向，合起來說出了一件什麼樣的事」，而那件事要**在文章裡被一步步兌現**。

**投影對所有題目都要求「推進」；只對真正的爭議題要求「對立」。** 把立體群像題硬找一個辯論論點 = 製造 contrarian thesis = 炎上（金曲獎 v1 教訓）。但立體群像題沒有推進的論點 = 回到面向導覽的老病。兩邊都要避開。

### 動作 2：設計骨架（一串「動作」，不是一串「面向」）

骨架是文章推進論點的**一連串動作**。每個動作是一個**動詞**，不是一個名詞主題：

- ❌ 面向骨架（名詞）：創辦人 / 第二任總編 / 紙本與網站 / 年度名單 / 商業活動 / 信任問題
- ✅ 動作骨架（動詞）：立起悖論 → 找出這本事從哪來 → 看它怎麼長成一個機制 → 掀開機制的陰影 → 把最後一步交還讀者

**Shuffle test（骨架的驗收）**：把 section 順序打亂，論證有沒有斷？沒斷 = 你排的是目錄，重排成論證。真正的骨架，重排就讀不通，因為第三步預設了第二步、第四步預設了第三步。

骨架有**形狀**：鋪陳 → 深化 / 複雜化 → 轉 → 收。（不是編年、不是面向巡禮。）depth 文 3-7 個動作。

### 動作 3：給每個 section 雙重職責（局部 + 全局）

每個動作 / section，藍圖要寫清楚四件事：

1. **局部承載**：這一段從研究報告拿哪些事實 / 場景 / 引語（指向 research §）。
2. **全局功能**：這一步**替論點做了什麼**？（把悖論立起來 / 給論點一個來源 / 證明論點的機制 / 掀開反例……）——**這是抗目錄的關鍵**。一個 section 如果全局功能只有「介紹某面向」，它就是目錄條目，要嘛給它一個全局功能，要嘛砍掉。
3. **扣回主軸**：這一段哪一個 beat 跟主軸錨**押韻**（同一個錨點的變奏，per [EDITORIAL §核心矛盾 anchor 整篇貫穿](EDITORIAL.md)）。
4. **進出連結**：接住上一段的什麼、拋給下一段什麼（per [EDITORIAL §段與段的呼吸](EDITORIAL.md) narrative bridge）。

### 動作 4：減法（明確列出砍掉什麼、為什麼）

研究報告一定比文章能裝的多。投影**明確列出砍掉的材料 + 理由**。砍的判準：

- 不服務這一次的論點
- 跟一個更強的 beat 重複
- 會稀釋骨架的推進
- 有趣但岔題（進腳註，或留給另一篇文章）

減法是投影對**密度失衡**（[EDITORIAL §密度平衡](EDITORIAL.md)）的根治：不是寫的時候克制，是**寫之前就決定不寫**。列不出減法 = 你打算把研究都塞進去 = 保證寫成 CV。

### 動作 5：echo map（把主軸錨在每個 section 押韻一次）

主軸錨在 description + 開場 + 中段 + 結尾各出現一次，這是 EDITORIAL 既有規則。投影把它**升成每個 section 一次的地圖**：section → 這一段用什麼方式回到那個錨。

**錨點反覆出現、每次變奏，本身就是那個「宏大抽象的敘事」。** 讀者感覺到有一條線穿過全文，不是因為你在開頭宣告了主題，是因為每一段都用不同的方式碰到同一個核心。這是 echo map 要保證的事。

### 動作 6：審定文風與結構（把決定前移到寫之前）

投影順手把寫手容易即興的東西先定下來：spine 類型、標題冒號三明治的雛形、結尾畫面（結尾先行）、視覺化模組要放哪幾個（指向 [graph.md](graph.md)）、媒體分鏡。寫手因此是**執行一個已經想清楚的結構**，不是邊寫邊發明結構。

## 四、投影藍圖 產物模板

> Filename：`reports/article-projection/{slug}.md`。寫手把這份當**主要規格**讀，研究報告當**材料來源**讀。

```markdown
---
article: knowledge/{Cat}/{slug}.md
researchReport: reports/research/{YYYY-MM}/{slug}.md
spine_type: 立體群像 | 矛盾驅動
projection_done: true
date: YYYY-MM-DD
---

# {slug} — 投影藍圖

## 1. 論點（一句話，有張力、要被賺到）

{一句話。矛盾驅動＝可被反駁的主張；立體群像＝有推進的統合洞見。附一行：這句話為什麼不是摘要（讀者能不同意什麼 / 文章要證明什麼）。}

## 2. 骨架（動作序列，過 shuffle test）

1. {動詞：這一步做什麼} —— 對應 section「{暫定標題}」
2. {動詞} —— section「…」
   …
   （一行說明：為什麼這個順序不能打亂——第 N 步預設了第 N-1 步的什麼。）

## 3. 每個 section 的雙重職責

### section 1：{暫定 H2 小標 — 給讀者看的，不是內部動詞}

- **暫定小標**：{場面／物件／數字／人話命題；須通過 EDITORIAL §小標「主–述–賓還原測試」}
- **還原句**（給自己看）：{誰／什麼 + 動作或狀態 + 著落，一句}
- 局部承載：{研究 §X 的哪些事實/場景/引語}
- 全局功能：{這一步替論點做了什麼 — **內部用語，禁止直接當 H2**}
- 扣回主軸：{哪個 beat 押韻主軸錨}
- 進出連結：{接住上段的 X / 拋給下段的 Y}
  （每個 section 一組）

> 小標 vs 全局功能：全局功能是編輯室術語（「立起悖論」「機制放大」）；站上 H2 必須翻譯成讀者聽得懂的載體句。詳見 [EDITORIAL §小標題](EDITORIAL.md)。

## 4. 減法（砍掉什麼、為什麼）

- 砍 {研究裡的某材料}：因為 {不服務論點 / 重複 / 稀釋 / 岔題}
  …

## 5. echo map（主軸錨的變奏）

- 主軸錨：「{一句}」
- 開場：{怎麼碰它} / section 1：{變奏} / … / 結尾：{最後一次變奏}

## 6. 審定

- spine 類型：… / title 雛形：「主題：副標 hook」/ 結尾畫面（先行）：… / viz：{tw-\* 哪幾個，各回答什麼資料關係} / 媒體分鏡：…
```

## 五、投影 gate（什麼樣的藍圖算過）

Step 2.0 過這五題才准派寫手（HARD）：

1. **論點不是摘要**：那句論點，讀者能不同意，或文章非證明不可。是「X 是重要的 Y」型 → 退回重找。
2. **骨架過 shuffle test**：section 順序打亂會讀不通（第 N 步預設第 N-1 步）。能隨便重排 → 還是目錄，重排成論證。
3. **每個 section 有全局功能**：沒有任何一個 section 的職責只有「介紹某面向」。有 → 給它全局功能或砍掉。
4. **減法非空**：真的列出了砍掉的材料。列不出 → 你還沒做選擇，會寫成 CV。
5. **echo map 覆蓋全篇**：每個 section 都有一個回到主軸錨的 beat（不是只有頭尾）。

（v1.0 gate 是人眼判斷，跟 §觀點成型 同級。未來考慮 `projection-health.py` 儀器化 shuffle/echo/論點型別。）

| ❌ 反 pattern          | 病                                                     | ✅ 改                                                       |
| ---------------------- | ------------------------------------------------------ | ----------------------------------------------------------- |
| 面向巡禮（facet tour） | section = 名詞主題，可隨意重排，加法不是乘法           | 骨架改成動詞序列，每 section 給全局功能                     |
